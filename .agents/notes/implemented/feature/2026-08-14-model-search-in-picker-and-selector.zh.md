# Agent Note: 获取模型对话框与主界面模型选择器的搜索

Status: implemented

[English](2026-08-14-model-search-in-picker-and-selector.md) | 中文

## Problem

两个模型界面在列表很长时都没有按名称查找模型的方式。Models 设置页的"获取可用模型"对话框（ui-settings-models 的 `ModelListEditor`）把每个发现的候选模型列成一个复选框行；作曲家输入区的模型选择器（ui-model-selection 的 `ModelSelect`）按提供方分组列出所有广告模型。OmniRoute 部署已把目录精简到 13 个，但任何仍列出数百个模型的网关都会让两个界面变成逐行扫视。

## Decision

两个界面都增加文本搜索，只收窄可见范围，不触碰选择状态。

**获取对话框。** 搜索框位于批量工具条与候选列表之间。可见集是 id 或名称包含查询串的候选（不区分大小写的子串匹配）；被隐藏候选的复选框保持原状态，因此搜索是纯粹的视图过滤。"Select all"（全选）作用于可见（过滤后）的候选，而"Deselect all"（取消全选）始终清空整个选择——这种不对称是有意为之：两个按钮在每种状态下都按字面理解，全量清空是任何过滤后的恢复手段。没有候选匹配时，对话框显示无匹配提示而非列表。查询在对话框打开（`fetchModels`）与关闭（`closePicker`）时重置。

**主界面选择器。** 搜索框位于模型面板的模型列表上方。每个提供方分组只保留匹配的模型（id 或名称子串，不区分大小写），没有匹配的分组整体隐藏；全部分组都消失时菜单显示无匹配提示。查询在每次打开菜单时重置（`show()`）。焦点在条目列表之外（搜索框或触发器）时，ArrowDown/ArrowUp 从第一个/最后一个条目开始，而不是落在过期的索引上，使新增的可聚焦字段不会误导键盘导航。

文案均已本地化：ui-settings-models 为 `searchModels` / `searchNoMatch`（en 为源），ui-model-selection 为 `search.placeholder` / `empty.matches`（zh 为源）。组件测试覆盖过滤后的全选与全局取消全选、无匹配提示与恢复、id/名称匹配、大小写不敏感与空分组隐藏。

## Alternatives considered

**匹配串包含分组/提供方名称。** 未采用：模型才是选择的单位，提供方名称已作为各段上方的分组标题显示；按模型自身的 id 与名称匹配是最不意外的过滤器，提供方搜索属于提供方列表而非此菜单。

**过滤选择而非视图**（输入时取消勾选不匹配的行）。未采用：视图过滤从不令人意外——关闭对话框或清空查询会精确恢复用户做出的勾选——而在搜索中改动选择会毁掉用户已看不到的精选结果。

**边输入边仅选择匹配项。** 未采用：那会让输入具有破坏性。全选保持为显式手势，其"作用于可见集"的语义由工具条恰好位于搜索框下方这一点说明。

## Consequences

两个界面都不需要服务端或目录改动：过滤是组件内对已加载数据的本地操作。有意的不对称（过滤后的全选、全局取消全选）是唯一值得特别说明的行为，`provider-form.client.spec.tsx` 与 `model-select.client.spec.tsx` 中的测试覆盖了它。搜索在列表长到需要它之前不可见，每个界面只增加两个语言键。
