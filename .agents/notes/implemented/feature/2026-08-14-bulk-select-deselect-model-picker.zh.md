# Agent Note: 模型选择器中的批量全选与取消全选

Status: implemented

[English](2026-08-14-bulk-select-deselect-model-picker.md) | 中文

## Problem

Models 设置页的"获取可用模型"对话框（ui-settings-models 的 `ModelListEditor`）在打开时会预先勾选所有新发现的模型，而缩小选择范围只能逐行取消勾选。当一个网关列出数百个模型时（本部署的 OmniRoute 目录有 608 个），精挑细选变成几百次点击，且对话框没有任何批量重置选择的方式。

## Decision

候选列表上方新增两个批量控制，复用卡片头部动作的 `linkButton` 胶囊样式："Select all"（全选）勾选全部候选，"Deselect all"（取消全选）清空整个选择。采纳语义不变：已配置的行保留其调校过的容量（`byId.get(candidate.id) ?? adopt(candidate)`），因此重新勾选已知模型是无操作，而空选择会写入空的 `models` 数组，即恢复内置目录行为。文案通过 `locales.ts` 的 `selectAll` / `deselectAll` 键本地化（en/zh）。两个组件测试覆盖该控件：取消全选后空采纳，以及批量清空后用全选恢复所有行。

## Alternatives considered

**全选跳过已配置的模型。** 未采用："全选"按字面理解，且采纳路径已保证重新勾选已配置行是无操作并保留用户调校过的值，因此勾选全部始终安全，绝不会改写已修正的容量。

**单个切换按钮**（未全选时显示全选，全选时显示取消全选）。未采用：标签会在交互中途翻转，且目标状态无法从对话框允许的混合选择中推导，因此两个显式控件才是可预测的表面。

## Consequences

底部"添加所选"语义不变：未勾选任何项则不加任何行。代价是对话框多了两个控件；字面的全选可能勾选已配置的行，在采纳时表现为无操作——与对话框既有的"允许手动重新勾选已配置行"一致。
